## 🔓 Добро пожаловать в репозиторий sql_Brazilian_Dataset, проектирование аналитического DWH на базе Brazilian E-Commerce Public Dataset by Olist.   
Это проект для портфолио, его суть в демонстрации навыков создания хранилищ данных и получения из них аналитических метрик для бизнеса. 

## 🏅 Архитектура проекта:
Проект спроектирован по архитектуре Medallion и включает в себя таблицы слоев Bronze и Silver, а также представления слоя Gold и BI витрины для бизнеса.
- Бронзовый слой содержит одну исходную таблицу в сыром виде, формат csv.
- Серебряный слой — это разделение исходных данных на отдельные таблицы фактов и измерений с их последующей очисткой, дедупликацией и стандартизацией.
- Золотой слой реализован в виде представлений на основе данных из Серебряного слоя. Он содержит очищенные витрины данных, полностью готовые к бизнес-анализу.
- Семантический слой (Power BI): Прием чистых бизнес-сущностей из представлений SQL и развертывание логики для аналитики. Включает оптимизацию гранулярности фактов, ролевые измерения, расчет DAX-метрик и настройку динамической безопасности (RLS).

## 🔎 Обзор проекта:
Проект на базе СУБД MS SQL Server, включает в себя работу с архитектурой данных, их преобразованием, разработку новых таблиц и оптимизацию аналитических запросов.
Также содержит схему моделей, потоков и каталоги данных.

## 📊 Ключевые инженерные решения в Power BI:

- **Управление гранулярностью и разделение фактов:** 
  Исходный атомарный поток продаж разделен на две таблицы фактов разной гранулярности — по позициям товаров (fact_order_items) и по транзакциям платежей (fact_order_payments). Таблицы связаны через подтверждающее измерение (confirmed_dim), что позволило корректно рассчитывать e-commerce метрики стоимостей и объемов без риска задвоения данных.
- **Добавление новых справочников:**
  Выделены дополнительные измерения для чистоты модели. В частности, это измерение даты (dim_date), измерение статусов доставки (dim_order_status), измерение типов оплаты (dim_payment_type) и связующее измерение между двумя таблицами фактов разной грануляции (confirmed_dim).
- **Динамическая безопасность (Row-Level Security / RLS):** 
  Внедрена система разграничения прав доступа по географическому признаку. Через DAX-код к модели подключена служебная таблица (security), которая динамически фильтрует справочники клиентов и продавцов на основе их регионов.
- **Аналитические инструменты:** 
  Библиотека DAX-мер для расчета e-commerce показателей (Коммерция, логистика, эффективность продавцов\клиентов), спроектирован интерактивный дашборд.
  
## 📢 Требования к проекту

#### Цель: 
Разработать современное хранилище данных с использованием SQL Server для консолидации данных о продажах, что позволяет вести аналитическую отчетность и принимать обоснованные решения. 

#### Технические характеристики 
- **Источник данных**: Импорт данных из исходной системы, представленных в формате CSV-файла. 
- **Качество данных**: обеспечение целостности, очистка и дедупликация данных перед загрузкой в витрины. 
- **Фокус**: Анализ актуального состояния данных (историзация и отслеживание медленно меняющихся измерений.
- **Документация**: Предоставить чёткую документацию модели данных для поддержки как бизнес-заинтересованных сторон, так и аналитических команд.
